## Fixes and remaining release gates

1. **Android repository resolution:** HBuilderX generates settings repositories with `PREFER_SETTINGS`, which overrides the plugin's `project.repositories`. The helper changes this preference only in HBuilderX temporary dependency-resolution projects. The plugin still declares its public Maven repository and exact native version. The original HBuilderX Gradle preference was restored after verification.
2. **iOS callback removal:** Swift cannot compare callback functions using `indexOf`. Subscriptions now have numeric IDs, allowing removal without comparing functions. The UTS Swift compile passed after this change.
3. **Demo status:** the example now uses `MeshStream.getStatus(clientId)` at the Vue/JavaScript boundary, consistent with the static-helper recommendation. Telemetry refresh and graceful close still require runtime investigation and acceptance.
4. **iOS host:** the installed HBuilderX Uniapp simulator executable and DCloudUTSFoundation simulator framework are x86_64-only. Installed simulator runtimes support arm64 only. No code-signing identity was available for the connected iPhone. This limitation concerns the Uniapp host, not the published MeshStreamKit XCFramework architecture.

Before publication, resolve the Android telemetry wait and complete playback, P2P exchange, controlled CDN fallback, session isolation and close acceptance in a supported custom/cloud build. Obtain a signed iOS device custom base or an arm64 simulator host and repeat the iOS checks. Then update release documentation, regenerate and checksum the final package, push the release commit/tag, submit DCloud and verify installation of the exact market version in a clean app.

## Reproduce package preparation

Use new paths; the preparation script does not overwrite an existing staging directory or artifact:

```sh
python3 scripts/prepare-marketplace.py --project /absolute/new/staging-project --zip /absolute/new/meshstream-p2p-1.0.2-candidate.zip
/Applications/HBuilderX.app/Contents/MacOS/cli uni_modules --publish meshstream-p2p --project /absolute/new/staging-project --dryRun --json
```

The deterministic candidate ZIP is created by the preparation script. HBuilderX independently validates and dry-runs packaging of the same clean plugin files. Its temporary ZIP path is removed after the dry-run; the retained candidate ZIP must not be described as that transient file's byte-for-byte copy. Do not remove `--dryRun` until the runtime release gates are complete.


## Android device follow-up (2026-10-30)

The connected OPPO PFJM10 (Android 13, arm64) was tested with the isolated local custom host and the official DCloud cloud custom base. The local HLS fixture served 7 verified TS segments and recorded the original bytes and SHA-256 independently.

- Static `MeshStream.preload` returned `true`; configuration resolved to `OK`, tracker pool ready, quota available and effective P2P enabled.
- Two independent clients in one Android process connected to one peer. Receiver downloaded 1,942,604 bytes over P2P and 689,020 bytes over HTTP; measured download offload was 73.8177%. Seeder uploaded 1,942,814 bytes across 6 successful P2P segment uploads.
- All requested segment integrity checks passed. After closing the seeder, the receiver fetched an unseeded segment through CDN fallback. P2P-disabled mode produced zero P2P bytes. Diagnostics reported one successful ICE attempt and no ICE failures.
- Numeric event subscription/unsubscription, P2P toggle, position/buffer updates, idempotent close and proxy release passed on the local custom host. A JavaScript adapter now converts explicit UTS result callbacks into reliable Promise resolve/reject behavior; a negative closed-client call was caught in 199 ms.
- The official cloud custom base was installed on the same device. The customer Demo auto-started, rendered the input form, played the Mux HLS sample, and continuously updated stats; the captured screen showed the video and Telemetry panel.

This is same-device two-client evidence, not cross-device Android interoperability. iOS runtime acceptance remains pending.


The native proxy shutdown regression was reproduced with a keep-alive HTTP client: before the fix, `ProxyServer::shutdown` left established connections alive beyond one second. The proxy now tracks connection tasks in a `JoinSet`, aborts them during shutdown, and waits for all tasks. The focused Rust regression passed (1 passed, 239 filtered). The full native crate was not rerun because this checkout has no macOS libdatachannel build at the default path; the focused test used the pinned `.runtime` libdatachannel/mbedtls builds.
